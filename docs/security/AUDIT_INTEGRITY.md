# SentinelOps AI Audit Integrity

SentinelOps evidence exports include a tamper-evident manifest generated by `server/audit-integrity.mjs`.

## What Is Verified

- Approval signatures are recomputed from the signed payload and `previousHash`.
- The global approval ledger is checked as a newest-to-oldest hash chain.
- Evidence packet Markdown is hashed with SHA-256.
- Run, approval, policy-check, agent-review, and audit-event sections are hashed separately.
- The manifest itself receives a SHA-256 hash for audit handoff.
- Full audit exports hash all major datasets, include per-run evidence manifest hashes, declare the nonclassified portfolio data boundary, and receive a SHA-256 export hash.

## API Surfaces

- `GET /api/audit/integrity`
  - verifies the global approval ledger.
- `GET /api/audit/export`
  - returns the all-runs audit export with ledger verification, dataset hashes, run inventory, retention guidance, and export hash.
- `GET /api/runs/:id/evidence-manifest`
  - returns the run manifest without embedding the Markdown packet.
- `GET /api/runs/:id/evidence-bundle`
  - returns the manifest plus the Markdown evidence packet.

All three endpoints require the same `export_evidence` permission used by evidence packet export.

## Verification

Run:

```bash
npm run audit:check
```

The smoke test proves:

- a valid two-record approval ledger passes signature and chain checks;
- the generated manifest includes packet and section hashes;
- the full audit export includes dataset hashes, run manifest hashes, alert dispatch counts, retention guidance, and an export hash;
- payload tampering invalidates the approval signature;
- chain tampering invalidates the previous-hash link.
